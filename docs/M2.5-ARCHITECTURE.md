## 2. Journey state machine
Stored task status is unchanged (`not_started`, `in_progress`, `ready_for_review`, `awaiting_external_confirmation`, `completed`). The map shows derived labels:

| Stored | Official task (sponsor/government) | Other task |
|---|---|---|
| completed | **Externally confirmed** | Completed |
| awaiting_external_confirmation | Awaiting response | Awaiting response |
| ready_for_review | Draft ready | Draft ready |

Four separate status families, never merged: **task** (`journey_tasks.status`), **application** (`employer_applications.status`), **document** (future), **official confirmation** (`external_facts.status`: claimed / confirmed / rejected).

Employer ladder (applicant-reported, evidence required after "preparing"):
`saved` → save_first_opportunity · `submitted`+evidence → submit_first_application · `responded` → employer_replied (**not** a host) · `offer_received`+evidence → host_offer_received ("host identified, subject to sponsor verification"). None of these touch sponsor tasks.

Sponsor ladder: any saved sponsor → research in progress + shortlist · preferred → choose_preferred_sponsor (**a selection, not approval**) · sponsor accepts / reviews host / issues DS-2019 / visa decision → only an **external fact confirmed by an administrator** completes them. A claim moves the step to "awaiting".

Engine rules: forward only (never regresses started work); skips N/A tasks; unknown rule keys fail closed; N/A tasks are excluded from progress.

## 3. Additive migrations

* Seeds: backfill (adds v2 tasks to existing journeys), 9 clearly labelled **fictional** sample opportunities.
Nothing is dropped, renamed, or reset.

## 4. How existing records are preserved
Existing journeys are only touched by the backfill, which (a) inserts missing tasks, (b) re-routes applicability **only for untouched** (`not_started`) tasks, (c) never edits status, notes, or evidence of a started task. Old `has_host = true` answers become `host_state = 'interested'` (never `offer`). Verified by `tests/sql/upgrade_preserves_data.sh`.
The M1 trigger's evidence/dependency checks now apply to the `authenticated` role only, so confirmed external facts can complete a step without being blocked; applicants keep every old restriction.

## 6. Acceptance tests (all in `tests/sql/engine_scenarios.sql` unless noted)
* **A** no host/no sponsor: employer search and sponsor research both open; saving a listing and sending an email (with evidence) never completes "host"; a reply never completes "host".
* **B** written offer with evidence: host offer recorded; sponsor review and acceptance stay open; search tasks N/A.
* **C** sponsor already accepted: search steps skipped; acceptance cannot be self-completed; claim → awaiting → admin confirmation → "externally confirmed".
* **D** isolation: cannot read, write, or claim into another user's journey, drafts, dismissals, or resume folder. (Document/DS-7002 scenario belongs to the next slice.)
* Persistence: drafts, résumé choice, application status, evidence, and facts live in Postgres. Unit tests: `tests/unit/{engine,onboarding,matching,resume}.test.ts`.

## 7. Not built (by design)
No auto-apply, no email sending, no payments, no passport storage, no map animation or character, no sponsor-application or document tables yet. "Assisted help" is only a waitlist preference.
